# 第二阶段：前端开发

你是一名擅长移动端交互和适老化设计的前端工程师。请读取 `docs/需求设计.md`、`docs/接口约定.md` 和当前代码，按第一阶段确定的技术方案，实际开发“家庭药品管理助手”的前端。

本轮目标是得到可以启动、可以操作、页面完整的前端。后端尚未完成时，使用符合接口约定的 Mock 数据和适配层，方便第三阶段切换为真实服务。

## 设计关键词

移动端优先、适老化、大字、高对比、清晰层级、醒目主操作、图片辨认、少步骤、宽松触控区、友好反馈、空状态、加载状态、错误状态。

请自主设计一套适合家庭药箱的视觉方案，确定颜色、字体、间距和组件。页面要有完整产品感，避免把所有字段和按钮堆在同一个表单里。

## 需要实现的页面与流程

### 1. 首页与药品列表

清楚展示药品、有效期状态和主要操作。支持搜索、位置筛选与状态筛选；让老人容易找到“添加药品”和“查看详情”。有必要时显示临期、过期数量和提醒入口。

处理首次没有记录、搜索无结果、数据加载中、网络失败等状态。药名和位置较长时能够换行，状态同时使用文字和颜色。

### 2. 新增与编辑

完成照片拍摄或选择、图片预览、药品信息填写、位置输入、日期选择与保存流程。照片张数和字段规则遵守需求设计。

显示具体校验错误，保存过程中避免重复提交，失败保留输入。用户离开未保存的编辑页时提供明确选择。编辑时回填完整信息，删除需要确认。

### 3. 药品详情

展示清晰包装图、完整信息、位置和日期状态。支持查看大图以及返回。语音播报应通过独立、明确的操作触发，具体交互由需求设计决定。

### 4. 提醒与设置

按需求设计实现临期、过期提醒列表，以及提前天数、语音和联系人等必要设置。暂未接入的系统能力要准确展示状态，不用固定“成功”提示代替真实操作。

## 代码与接口要求

- 将页面组件、业务状态、日期计算、接口调用分开，避免单个文件承担全部逻辑。
- 前端统一通过服务层调用数据，不在页面里散落 Mock 数组。
- Mock 的字段、路由语义和错误格式必须符合 `docs/接口约定.md`。
- 提供明确的 Mock/真实 API 配置方式，接口地址集中管理。
- Mock 模式应有开发标识；临时演示数据不能被当成已经接入真实后端。
- 日期展示和状态遵守统一规则，不在多个页面各算一套。
- 相机、选图、语音等浏览器或设备能力需要处理不可用、拒绝和取消。
- 关键按钮、表单与图标有清晰标签；覆盖层、返回与键盘操作不会误触或丢失内容。

## 请实际完成验证

启动项目并检查：手机宽度下布局、搜索与筛选、新增/编辑/删除交互、图片预览、日期边界、必填错误、长文字、空状态和接口失败状态。

针对日期判断和组合筛选等关键逻辑做必要测试。能取得实际页面截图时保存到项目中；无法运行的检查如实记录。

## 本轮产出

1. 可运行的前端代码与明确启动命令。
2. 可替换的 Mock 和 API 服务层。
3. 更新 `docs/开发记录.md`：页面完成情况、测试结果、当前限制、第三阶段联调事项。
4. 若页面实现确需调整接口，先同步修改 `docs/接口约定.md`，注明变动，避免前后端各自定义。

请直接创建和修改代码、启动验证并修复本轮问题。本轮完成前端可演示流程即可，第三阶段负责接入真实持久化与后端任务。
