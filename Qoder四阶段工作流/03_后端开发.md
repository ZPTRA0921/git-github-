# 第三阶段：后端开发与前后端联调

你是一名后端工程师和全栈联调工程师。请读取 `docs/需求设计.md`、`docs/接口约定.md`、`docs/开发记录.md` 和已完成的前端，使用第一阶段确定的技术方案开发真实后端，并完成联调。

本轮目标是让应用从演示数据变为可持久化、可重启、可完整操作的产品。需要实际编写后端代码、启动服务、连接前端并验证。

## 开发关键词

REST API、数据库、真实增删改查、图片上传、存放位置、日期校验、临期计算、提醒任务、错误处理、配置管理、数据备份、本地部署、接口联调。

## 核心工作

### 1. 数据模型与持久化

依据接口合同建立药品、照片、位置、提醒和必要设置的数据结构。采用原型规模合适的持久化方案，保证服务重启后记录和照片仍可使用。

明确 ID、创建时间、修改时间、日期格式、照片关联与删除规则。不要把内存数组或固定返回值作为正式存储。第一版按需求设计的家庭使用范围实现，不无故增加复杂账号、权限或多租户体系。

### 2. 真实业务接口

完成药品新增、列表、详情、修改、删除，搜索、筛选和位置查询，照片上传与访问，以及提醒和设置接口。

字段校验同时在后端执行，不能只依靠前端表单。统一处理非法日期、空白名称、记录不存在、重复提交、图片过大或类型不符、存储失败等情况，返回前端能够理解的错误。

照片使用受控文件名和访问路径，数据记录与图片文件保持一致。删除记录和替换照片后，按设计清理不再使用的文件。不要要求用户手工修改服务器磁盘路径才能查看图片。

### 3. 日期与提醒

根据同一时区和日期规则计算正常、临期、过期状态，保证列表数量、详情状态和提醒结果一致。今天到期、提前天数边界、跨月和闰年要有测试。

按需求设计实现提醒记录及必要后台任务：定期检查、避免无意义重复、设置变动后更新、应用重启后补查遗漏。

必须区分三件事：服务器检测到期、生成应用内提醒、送达手机系统通知。完成其中一项不能宣称三项都完成；手机系统通知只有按选定平台真正接通后才能标为可用。

### 4. 前后端联调

先逐个验证真实接口，再将前端服务层切换到后端。检查字段、筛选参数、时间格式、上传协议、图片 URL、跨域或代理配置以及错误提示。

完成真实闭环：新增并上传照片 → 列表找到记录 → 查看详情 → 修改 → 重启服务后仍存在 → 删除后不再出现。

保留独立的演示数据初始化方式，重复执行不会无限新增重复记录。正式数据和测试数据要能区分。前端不得失败后悄悄回到 Mock 并仍显示“保存成功”。

## 运行与验证

提供清楚的依赖安装、配置、数据库初始化、后端启动和前端启动步骤。配置示例中不写真实密钥；不依赖作者电脑的绝对路径。

实际执行接口与联调检查，至少覆盖：

- 完整 CRUD 和照片上传访问。
- 关键词、位置、日期状态联合筛选。
- 无效输入、找不到记录、上传失败和存储失败。
- 日期边界及提醒去重、更新和重启补查。
- 服务重启后的数据留存。
- 前端真实 API 模式下的完整用户流程。

若需求设计明确要求安装包或系统通知，本轮补齐必要的平台集成与打包验证；条件缺失时记录准确缺口，完成其余可验证工作。

## 本轮产出

1. 真实后端、数据库初始化或迁移方式、图片存储和提醒任务。
2. 已联调的前端，默认指向明确配置的真实 API。
3. 更新后的接口文档、README 和运行说明。
4. `docs/开发记录.md` 中的真实验证结果、完成范围、待测项和当前演示路径。

请在现有前端基础上联调，不为适配后端随意推倒全部界面。遇到合同确实不合理的地方，协调修改前后端与文档，保持三者一致。
